# Mode: beta comments

1. **Gather.** For a Google Doc, follow `engine/beta-google-doc.md` ("Gather reader comments"). For pasted or emailed notes, ask which chapter each refers to if it isn't clear.
2. **Sort** each comment:
   - *Clear fix* (a typo, an unclear pronoun, a confusing word, a factual slip): apply it.
   - *Taste call* (a reader didn't like a line): list it for the author with a proposed fix.
   - *Story issue* (a reader is confused about what happened, or why): this is a signal, not a line edit. Find the cause (a missing explanation, a rule not shown yet, a knowledge slip) and propose a fix. If the fix touches canon or plot, route it through `/write-chapter` or `/book-plan`.
3. **Look for patterns.** The same kind of comment three times is a standing rule waiting to be written (that is how B9, the pronoun rule, and B15, the lay-reader rule, came about). Propose it for style guide section I.
4. Also look for edits the author made directly in the Doc and notes typed into the Doc text; bring them into the book.
5. Report which comment threads are handled, so the author can resolve them in the Doc.
